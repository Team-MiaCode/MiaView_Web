# KFC 网站外接 MiaCode Web 预览器改进计划

工作分支为 `standalone-preview`。案例为 https://kfc.holinality.com/charts/100 。本计划依据目标站公开 HTML、客户端脚本、CSS、资源 HEAD 响应，以及当前仓库源码。

## 案例现状

目标页为 Next.js/React 谱面详情页，作品为 Spade，难度为 MASTER 13+，难度 key 为 5。主体包含播放器卡片，侧栏包含曲目信息、难度选择和下载分享入口。

播放器通过 `/maichart/player.html?site=1` 嵌入。父页面读取谱面、音乐与封面，再通过消息交给 iframe。视频以 URL 传入。首次播放通知父页面，父页面按当前作品记录一次浏览量。

| 项目 | 页面公开实现 |
| --- | --- |
| 谱面 | `/api/files/100/maidata.txt` |
| 音乐 | `/api/files/100/track.mp3` |
| 封面 | 优先使用 Next 图片优化接口，原始文件为 `/api/files/100/bg.jpg` |
| 视频 | `/api/files/100/bg.mp4`，由 `hasVideo` 决定是否传入 |
| 难度 | 侧栏的 `difficulty` 状态与播放器联动，当前页面选择 key 5 |
| 归档状态 | `assets_archived` 控制页面显示归档说明或播放器 |
| 统计 | 首次实际播放触发网站的浏览量记录逻辑 |

上述四个文件的匿名 HEAD 请求均返回 200。该结果确认当前公开作品的资源可达性，实际解码、登录作品和跨来源访问纳入实施验收。

## 交付结构

外接入口沿用 `createPreview(container, options)`，返回现有 SDK 实例。接入方提供容器与资源，MiaCode 提供完整预览面板及播放能力。

建议使用当前 SDK 的 iframe 隔离边界，把完整面板接入 renderer 内部。一个实例包含一个 iframe 和一个预览引擎，面板与引擎通过现有 `createPlayerController` 交互，宿主调用通过现有 `attachSdkBridge` 进入同一控制器。

- `controls: true` 呈现完整预览面板，包括标题、画面、进度、播放控制、统计和两种设置覆盖层。
- `controls: false` 提供画面，由编辑器等宿主装配控制区。
- `products/preview/` 承担独立使用和演示入口，通过同一 SDK 挂载播放器。打开文件、选择媒体和示例谱面属于演示宿主。
- 公共面板复用 `ui/workbench/preview-panel.mjs`、`PreviewTransport`、`NoteStatistics` 和现有设置组件。挂载、命令及资源服务消费显式实例上下文。
- iframe 内部统一拥有主题、设置、菜单和事件监听。销毁实例时释放引擎、音频、媒体、观察器和订阅。

这项改进集中于现有 SDK 的完整面板能力。对外类型、资源字段、命令与事件沿用当前定义。

## KFC 接入映射

| 网站现有职责 | MiaCode 接入方式 |
| --- | --- |
| iframe 加载完成后的延时发送 | 等待 `preview.ready`，随后调用 `load()` |
| `files.maidata` | `load({ maidata })`，接受现有 Blob |
| `files.track` | 映射为 `audio` |
| `files.cover` | 映射为 `cover` |
| `files.videoUrl` | 映射为 `video`，转成绝对 URL |
| 侧栏难度选择 | `selectDifficulty(difficulty)`，成功后以返回的 `difficultyId` 更新选择状态 |
| 首次播放消息 | 订阅 `playing`，由网站按 chartId 去重并调用已有统计逻辑 |
| 音乐下载进度 | 网站继续显示其下载进度，播放器通过 `progress` 提供解析和准备阶段 |
| 页面跳转或组件卸载 | 取消宿主资源请求，调用 `destroy()` |

网站适配层负责把现有文件字段映射为 SDK 字段。播放器公开协议统一使用 MiaCode 的会话、来源、请求编号和构建身份校验。

React 组件以容器 ref 创建实例，effect 清理时销毁。chartId 改变时开始新一代加载，并取消前一代宿主请求。异步结果按当前 chartId 和加载代次应用。初始化期间的难度操作记录最终选择，谱面加载完成后应用。侧栏由网站拥有难度状态，播放器设置面板呈现预览与音频参数。

## 资源与部署

第一阶段采用网站同源静态部署，例如 `/miacode/sdk/`、`/miacode/renderer/` 与配套 UI、资源目录。SDK 和运行时以完整版本一起发布，使用现有构建身份与资源清单核对。

KFC 适配层继续通过网站自己的 fetch 获取谱面、音乐和封面 Blob，复用现有权限及图片回退逻辑。视频传入完整 URL。对需要登录态的视频，由宿主完成授权获取后传 Blob，或使用网站签发的资源 URL。

KFC 图片接口会协商 WebP/AVIF。实施时验证返回图片格式与当前解码路径，原始 `bg.jpg` 保留为网站现有回退来源。

接入方从 `ready`、`progress`、`error` 和 `load()` 的结果呈现初始化、加载、就绪和失败状态。统计以实际 `playing` 事件为依据。加载就绪后由用户点击播放。

## 尺寸与设置

网站为播放器容器分配高度，预览面板宽度按高度和 741∶865 比例计算。视口与侧栏变化时由网站调整可用高度，播放器保持比例。当前网站的 iframe 高度使用容器宽度加 124px 计算，接入时改用宿主明确的高度约束。

预览设置和音频设置的半透明背景覆盖整个画面容器，四边与画面贴合。进度条、播放控制和统计位于覆盖层外。菜单、焦点和键盘操作由对应实例管理。

网站金色主题由网站管理，播放器通过 `theme` 和 `setTheme()` 使用自身色板。用户设置提供显式的持久化范围或存储键，同一播放器实例的临时状态独立维护。

## 功能对照

| 当前网站播放器能力 | 改进工作 |
| --- | --- |
| 播放、暂停、重播、拖动、倍率 | 复用现有 SDK，完整面板提供操作入口 |
| 难度切换 | 与右侧难度列表建立单一状态来源 |
| 流速、背景亮度、背景视频 | 对接 `setSettings()` 与 `setMediaSettings()`，核对数值含义 |
| 音量、判定音 | 使用现有音频通道及 `audioCommand()`，按实际听感与有效增益验收 |
| 帧率 | 使用 `setPerformance()`，保持网站选择与生效状态一致 |
| 全屏 | 对整个面板提供全屏入口，全屏内包含播放控制及两种覆盖层 |
| 镜像、星头旋转、正解音偏移、播放偏移 | 建立逐项语义对照，确认共享核心能力，补充对应预览参数、类型和命令后验收 |
| 原版贴图、引导环、滑条旋转 | 对照现有皮肤和显示配置，核对实际效果 |
| 载入封面与首次播放引导 | 使用封面和加载状态，点击后启动当前实例 |

公共能力评估如下。字段名为设计建议，现行 SDK 契约以 `sdk/index.d.mts` 为准。

| 能力 | 公共语义 | 实现依据 |
| --- | --- | --- |
| 预览镜像 | 预览画面和判定点采用原向、水平镜像、垂直镜像或旋转 180°。播放时间与谱面源文件保持原值 | 归入预览设置，沿用项目坐标和判定区定义 |
| 星头旋转 | 控制 Slide 星头沿轨迹运动时的旋转效果。轨迹、判定点与计时保持原值 | 归入预览设置，接入现有星头姿态计算 |
| 正解音偏移 | 相对谱面时间调整正解音调度，单位为秒，正值延后 | 原生预览音效时间线采用 `answerOffsetSeconds`，可复用该字段和调度语义 |
| 音乐偏移 | 相对谱面时间调整背景音乐起点，单位为秒，正值延后。预览进度和 PV 仍使用谱面时间 | 归入音频设置，参考原生背景音乐时间偏移，WebAudio 同步验证播放、拖动、倍率和重播 |

预览镜像的作用域为播放实例，文档变换的作用域为谱面数据。校准参数服务于测量过程。扩展公共能力时，以各自作用域和时间基准定义参数。

## 实施与验收

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| P1 完整面板外接 | 接入 renderer、控制器和 SDK，整理样式及实例生命周期 | 外部容器调用 `createPreview()` 可获得完整面板，类型和示例匹配 |
| P2 网站适配示例 | 提供 Next.js/React 接入示例，覆盖 Blob 加载、视频 URL、难度、事件和卸载 | 模拟 KFC 的曲目栏、难度侧栏和播放器，应用方替换播放器组件即可接入 |
| P3 行为对齐 | 对照当前网站的功能清单，补齐全屏、加载引导及专项预览参数 | 同谱面、同难度、同参数下验证播放和显示结果 |
| P4 场景验收 | 本地案例页、资源与路由切换、生命周期、浏览器矩阵 | 验证通过后形成可部署包和接入说明 |

验收覆盖以下场景。

1. Spade 的谱面、音乐、封面、PV 加载，MASTER key 5 与网站侧栏一致。
2. 使用额外的多难度样本检查切换及初始化期间的连续选择，浏览器返回后实例状态对应当前页面。
3. 首次播放通知次数与网站统计规则一致，暂停恢复和重播继续消费同一作品实例。
4. 两种设置覆盖整个画面，打开时可拖动进度条及播放暂停，全屏状态具有相同操作。
5. 同一页面两个实例、React 挂载与卸载、加载途中离开、连续切歌，分别核对声音、渲染、事件与资源释放。
6. 公开与需要登录的资源、加载失败和重试、图片协商格式、视频缺省、归档作品状态。
7. 验收页面在本地记录首次播放事件，线上业务统计保持网站既有运行流程。

构建沿用 `build-devtools/` 与 Release，覆盖现有测试、SDK 类型、运行时身份、产品依赖闭合和静态打包。renderer 变更按仓库流程生成配套运行时。临时测试文件在验收后清理。
